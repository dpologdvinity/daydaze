# Free opencode models: what they're good at

Notes for the owner on the free models available through `opencode` (v1.18.7, `~/.local/bin/opencode`), from real tests on this project. Updated as more tests run.

## How to run one

```bash
opencode run -m opencode/<model> --dir <folder> "<task>"
opencode run -m opencode/<model> -f image.png -- "<question about the image>"   # attach files
opencode models | grep free                                                       # list free models
```

The model goes after `-m` as `opencode/<name>`. (The "orchestrator runner" script suggested by Google was broken: it closed `case` with `case` instead of `esac` and passed the model as a plain argument.) Give each model its own git worktree so it can't disturb other work, and always re-check its result before merging.

## Test 2: benchmark (running)

Four small tasks per model, same prompt for each, scored automatically where possible:

1. **Code**: implement `formatDuration` so a given test file passes (edge cases: NaN, negative, hours).
2. **Bug fix**: find the bug in an inventory stack function so its failing test passes, without editing the test.
3. **Code review**: spot planted bugs in a diff (a lost `price <= 0` guard, unvalidated `parseInt` from localStorage).
4. **Vision**: read a game screenshot (animals and counts, sign text, button labels).

Files here: `README.md` (this), `run.sh` (the benchmark runner), `tasks/` (the four tasks; `tasks/review/ANSWER.txt` lists the planted bugs). The raw per-model outputs and `results.txt` land in `runs/` when the run finishes (it runs from /tmp/oc-bench).

## Verdict

- Every working model passed the small code and bug-fix tasks, so for simple, test-checked jobs they are all usable. The differences show in judgment, speed and vision.
- Pick: **glm-5.3-flash-free** for general small tasks; **mimo-v2.6-flash-free** or **deepseek-v4.1-flash-free** for reviews; **nemotron-3.5-super-vl-free** (or glm/mimo, which also read images here) when a screenshot must be read; **nemotron-3.5-lightning-free** when speed matters most. Skip nemotron-3-ultra (unavailable) and flint (slow).

## Verdict so far (earlier notes)

- Useful for small, mechanical, clearly specified jobs (config updates, boilerplate, simple fixes) when the task says exactly how to verify.
- They tend to skip verification steps, so re-run tests/lint yourself before merging.
- Not for big features or anything that needs judgment about game design or visuals.
